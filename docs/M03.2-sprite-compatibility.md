# M03.2 — Generic sprite compatibility and local-only integration

Baseline: `13d28e8e4929a5d1e3b6894440588b9d42091172` (M03.1 PR #11). This PR contains generic compatibility code, original synthetic tests and an unverified Sonic audit template. No Sega artwork, source rectangles from Sega sheets, private outputs or private visual acceptance materials are included. Sonic is the sole initial target; no other roster or Trestle/Vela artwork is produced.

## Architecture and manifest v2

The fixed 60 Hz simulation, CPU policies, input, match rules, gameplay values and presentation capture are unchanged. All `src/core` sources, all 600 baseline tests and deterministic reports are protected by byte hashes in `reports/M03.2-preserved-files.json`. The public registry and existing public assets are unchanged.

Manifest v1 remains valid and retains canonical five-authored/eight-logical mirroring and role tint. V2 adds these fields while preserving every existing animation key:

```json
{
  "schemaVersion": 2,
  "palette": "native",
  "directionOverrides": {"w":{"source":"w","mirror":false}},
  "frames": {
    "pose-e": {"page":"page-0","x":2,"y":2,"width":64,"height":64,"trimmed":false,"rotated":false,"attachments":{"hand":[46,34]}}
  },
  "animations": {
    "idle": {"ticksPerFrame":10,"directionOverrides":{"w":{"source":"e","mirror":true}},"directions":{"e":{"loop":["pose-e"]}}}
  },
  "coverage": {
    "idle": {"w":{"kinds":["direct","held","mirrored"],"verified":false,"note":"Owner source audit pending"}}
  }
}
```

This abbreviated example is not a loadable package: all header fields, pages, baseline authored directions, phases and 28 × 8 coverage entries are mandatory. The standard directions remain N/NE/E/SE/S, with NW→mirrored NE, W→mirrored E and SW→mirrored SE. V2 can supply explicit additional views and overrides. Precedence is requested animation override → first inherited alias override → character override → base direction map. An exact authored west pose needs west frames; it cannot point at a nonexistent direction. A directional approximation must explicitly include `approximate` coverage.

Coverage kinds are `direct`, `aliased`, `held`, `mirrored`, `approximate`; multiple kinds can apply. Every cell has a verification boolean and explanatory note. Validation requires reporting aliases, one-frame holds, mirrored mappings and mismatched-heading approximations. Reports include the resolved source, mirroring, ordered frame sequences and phase frame counts. An asset's `verified` flag is a supplied audit statement, not an independent legal or visual certification.

Per-frame attachments override character attachments and mirror with the selected clip direction. The ground pivot remains (32,56). Native palette mode removes role-color multiplication; simulation-driven hit flashes remain. No manifest field can change gameplay timing, damage or movement.

V2 requires 64 × 64 untrimmed/unrotated rectangles, two-pixel transparent packing margins, non-overlapping distinct cells, at most 675 unique cells and three pages no larger than 1024 × 1024. Identical rectangles may have multiple labels/attachments. Baseline authored clips remain complete, even when logical mappings are overridden. V1 validation does not acquire these new packing restrictions.

## Offline normalization

The pure `normalizeFrames(recipe, decodedSources)` function uses explicit source PNG rectangles, ordered clip sequences and per-frame semantic roots. It never infers a grid or changes combat coordinates.

```json
{
  "schemaVersion": 1,
  "frames": {
    "pose-e": {
      "source":"source.png",
      "rect":[0,0,12,12],
      "root":[6,10],
      "attachments":{"hand":[8,4]}
    }
  }
}
```

The full recipe also supplies `character` manifest data and a provenance declaration. The original synthetic fixture demonstrates this example: a source pixel at (2,2) is translated to (28,48); attachment (8,4) becomes (34,50). Runtime pivot stays (32,56).

```text
runtimeX = sourceX - sourceRootX + 32
runtimeY = sourceY - sourceRootY + 56
```

Roots are relative to the selected source rectangle and may be outside it for a virtual ground reference. The converter copies visible RGBA channel values exactly, including white and partial alpha. Fully transparent pixels are canonical transparent zeroes. It does not rescale, center, quantize, recolor, crop visible overflow or guess a matte. PNG input supports non-interlaced indexed/grayscale/RGB/RGBA formats, supported palette transparency and filters 0–4. Adam7/interlaced and 16-bit PNGs are rejected. GIFs, ROM files and compressed game tiles are not input formats. Color-profile/gamma transformations are not applied; source originals remain preserved for comparison.

Exact normalized pixels are deduplicated using a hash bucket plus byte equality, not a lossy image comparison. Original frame labels, attachments and sequence order remain. The deterministic packer places 64-pixel frames in 68-pixel padded cells. Budget overflow is rejected without dropping poses.

CLI:

```sh
npm run sprites:normalize -- \
  --source-dir /absolute/owner-package/source \
  --recipe /absolute/owner-package/conversion.json \
  --out /absolute/owner-package/normalized
```

Inputs, recipe and output must be outside the checkout. Source/output folders must be separate; output must be empty/new. Source originals are only read. The normalizer resolves source paths, decodes PNGs and writes normalized PNGs, manifest, provenance and frame/coverage reports into the external output directory. Visible overflow returns `rejection-report.json` with source/root/normalized bounds; it produces no accepted atlas. Package ceiling violations are also reported without discarding poses. Measured exceptions require Master approval, not silent accommodation.

Provenance declares `rightsHolder`, `source`, `permissionBasis`, `redistribution` (`restricted-local` or `original-fixture`), source hashes and recipe hash. The tool records authorization as owner-declared/unverified. It does not infer rights from possession of a sheet or from private use.

## Local-only development workflow

```sh
npm ci
npm run dev:local-sprites
```

This dedicated server binds to `127.0.0.1:4183`, accepts no host/filesystem overrides, and rejects non-loopback configuration. The development UI additionally requires a loopback browser hostname. It is opt-in and excluded from ordinary development unless enabled, and any production build with local mode enabled fails.

Select these normalized files explicitly in the browser:

- `manifest.json` (v2, complete coverage)
- One to three PNG atlas pages
- The declared provenance JSON
- Optional `coverage-report.json`

The file-map provider has no `fetch`, arbitrary filesystem, storage or analytics path. It resolves only selected basenames, rejects duplicates/URLs/path traversal/missing pages, checks compressed size and PNG dimensions, and validates the manifest/provenance. The ordinary URL asset loader retains its existing same-origin behavior and does not gain filesystem access.

Private pages use fresh `private-local-*` texture identities rather than the public asset cache. Temporary Blob URLs are revoked after decode or cancellation. Explicit unload, cancel, scene shutdown/restart and rematch release session textures and file selections. Returning to menu also unloads; ordinary round transitions keep the selected package. Initial Start preserves a package selected in the menu. No private data is persisted or uploaded.

P1 receives the selected package; P2 remains synthetic. Fallback is selected valid package → existing original synthetic sprite → existing geometric renderer. Runtime missing-texture/frame failure returns to synthetic and releases the failed lease. No private package is copied into the registry or public asset tree.

## Artifact separation

`.gitignore` is not the boundary. `reports/public-asset-inventory.json` pins all five approved public files and the public registry hash. A Vite build-start gate recursively inspects public files, rejects symlinks, unapproved files/hash changes, and unapproved tracked binary assets. Ignored/untracked private files in `public` therefore also fail. Standard build output rejects extra binary assets and the private-import interface markers. CI artifact scans reject known external canary package bytes/markers; local-import tests publish only aggregate original-fixture metrics, never selected package files or screenshots.

Public browser tests use the existing original synthetic assets. Local-import browser tests generate an original canary package in OS temporary storage, select it through the browser file input, test native colors/fallback/cleanup, scan artifacts, and delete the package. No actual owner assets are present in CI. The compiled M03.1 presentation fixture also excludes the private import UI; private tests use the dedicated development server.

These checks prevent accidental inclusion through the supported workflow; they do not claim to recognize arbitrary copyrighted imagery embedded manually in source code. The release inventory is intentionally an allowlist: future approved original public artwork requires a reviewed inventory update.

## Sonic audit and remaining acceptance

`docs/art/sonic-coverage-template.json` lists all 28 states, all five baseline authored views and eight planned logical mappings. Every actual source sequence, order, frame bound, root, direction and permission field is **unverified** because no authorized owner-supplied package was available. No public archive was automatically downloaded. No full Sonic visual compatibility or private visual acceptance is claimed.

Owner-local acceptance must select an authorized source package, document its permission basis, fill the audit template, confirm all sequence orders/directions/semantic roots, review every alias/hold/approximation, inspect clipping/foot stability/jumps/guard/hit/KO/special cues, and rerun the local browser workflow. Directional approximations remain explicitly reported. Asset rights and visual acceptance are not inferred from passing generic tests.

Limitations: PNG input subset only, no auto matte removal, no scaling/oversize exception, explicit five-view baseline, no automatic animation recognition, no persisted private imports, and no source-specific Sonic mapping or timings. Synthetic/public assets remain the default, and Trestle/Vela remain deferred original-art paths.

Independent review should focus on v1 compatibility, override/alias resolution, normalization diagnostics, file isolation, texture ownership/cancellation and release-inventory boundaries. Open one code-only PR and leave it unmerged. No deployment, Cloudflare/hosting/visibility change, multiplayer, CPU retuning or roster expansion is included.
