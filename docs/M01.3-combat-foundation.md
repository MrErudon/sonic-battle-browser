# M01.3 — Combat Foundation

Based on `main` at `ecf4607` (merged PR #2, including event-driven jump input).
Branch: `feat/m01-3-combat-foundation`. This milestone is for review; do not merge automatically.

## Play and controls

Run `npm ci` and `npm run dev`, then focus the game. P1 is cyan; P2 is an amber
training target with neutral input. Move into reach and face the target.

| Control | Action |
| --- | --- |
| WASD / arrows | Eight-direction screen-relative movement |
| Space | Jump (one press, no auto-repeat) |
| J | Light attack |
| K | Heavy attack |
| R | Restore both fighters' positions, health, actions and effects |

Both ground and aerial attacks work. HP is shown numerically and as bars. Labels
show locomotion and action phase. Thin colored trails indicate startup, thick
trails/rings indicate active attacks, gray indicates recovery, and white bodies
indicate hitstun. Hits create fading spokes for 180 ms. Zero HP disables controls
and further damage; R starts another training attempt. There is no match flow yet.

## Architecture and tick contract

- `src/core/movement.ts` remains unchanged: locomotion, normalized movement,
  gravity, jump/landing transitions, facing and arena projection.
- `src/core/combat.ts` adds `CombatFighter`, extending the movement model with
  **separate** `action` (`ready`, `attack`, `hitstun`, `ko`), health, cooldown and
  knockback. `FighterStats` configures movement, hurt volume, HP, drag and four
  ground/air light/heavy definitions. No Phaser imports or wall-clock timing.
- `stepCombat` advances exactly one 60 Hz tick. The scene retains M01.2's
  accumulator and 100 ms maximum catch-up per render. Excess time after a long
  stall is intentionally dropped, not fast-forwarded.
- Each tick advances previous action timers, applies movement/gravity and
  knockback, consumes new attack intent, gathers active contacts, then applies
  damage/reactions. Simultaneous active strikes trade, including lethal strikes;
  neither fighter receives an advantage from list order in this two-fighter setup.
- An attack starts on frame 1. For light: frames 1–5 startup, 6–8 active, 9–18
  recovery. Frame 19 returns to ready and starts the extra 4-tick cooldown;
  frames 20–23 consume cooldown, and a fresh press can start on frame 24.
  Recovery and cooldown accept no buffered attack. No cancels or combo chaining.
- Hitstun begins when hit; its configured number of subsequent ticks lock
  movement, jump and attacks, including its last tick. Getting hit interrupts any
  attack phase. Hitstun replaces recovery and guarantees a minimum attack lock;
  it does not resume the interrupted action. KO still permits gravity/knockback.
- Ground attacks lock movement and jumping once started. The initial tick reads
  movement/jump first, so direction+attack aims the move and jump+attack selects
  the air definition. Air attacks retain reduced air steering and lock facing.
  Landing does not cancel an aerial attack. Cooldown permits movement and jumps.

## Input lifetime

DOM keydown listeners run independently of render updates. Jump and attack edges
survive release and zero-tick renders until the first simulation tick consumes
them; later ticks in that render receive no edge. Repeated keydown events are
ignored. Multiple jump taps coalesce; if J and K arrive before the same tick,
the **first attack wins**. This is scheduling, not a combo input buffer.

Eligibility is evaluated on consumption. Attacks consumed during startup, active,
recovery, cooldown, locked landing, hitstun or KO are discarded. Jump presses
consumed airborne, during locked landing or during an action lock are discarded.
The M01.2 landing-unlock tick still accepts new inputs. Space+attack on the same
eligible tick starts an aerial attack. R clears pending attacks/jump and effects.
Window blur and Phaser blur clear all pending input, held movement and partial
tick time. Scene shutdown removes DOM/game listeners and clears transient effects;
scene creation restores fresh fighters and input state.

## Geometry and hit reactions

The hurt volume is a circular arena footprint extruded from `z` through
`z + hurtHeight`. Each attack uses an oriented rectangle from the attacker's
origin forward to `reach`, with a configurable width, bottom offset and height.
Facing converts the existing eight screen directions through the inverse arena
projection, then normalizes. Collision uses rectangle-versus-circle closest
points and vertical interval overlap. Edge contact counts; diagonals use the
same reach in arena units. Geometry never reads sprite pixels or animations.

An attack instance owns a set of target IDs it has hit, so leaving/re-entering
cannot cause repeat damage. A later attack gets a fresh set. Fighters must have
unique IDs. Health clamps at zero. Heavy attacks launch; light attacks preserve
the target's current vertical motion. Horizontal velocity follows locked attack
facing, decelerates by 600 units/s², and continues independently of locomotion.
Footprint bounds clamp every tick. A launch clears landing lock so gravity cannot
be suspended. There are no wall bounces, body-to-body push collisions, damage
scaling, guard, invulnerability or continuous swept collision in this milestone.

## Provisional tuning and specification alignment

Read the accessible chats **2 Combat mechanics recreation** and
**3 Art Animation UI Planning** on November 15, 2026. Chat 02 calls all exact frame
data proposed, and recommends separate arena x/y and jump z, 60 Hz simulation,
100 HP, single-hit registration, and gameplay-owned attack timing. This milestone
uses its Light 1, Heavy and Air timing/damage suggestions below. These values are
not claimed to reproduce measured GBA behavior.

| Move | Startup / active / recovery | Extra cooldown | Damage | Hitstun | Speed / launch | Reach × width | Vertical bottom / height |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Ground light | 5 / 3 / 10 | 4 | 5 | 12 | 150 / 0 | 58 × 36 | 6 / 34 |
| Ground heavy | 12 / 4 / 20 | 8 | 15 | 24 | 320 / 180 | 76 × 44 | 4 / 42 |
| Air light | 7 / 4 / 14 | 4 | 9 | 12 | 150 / 0 | 58 × 36 | -12 / 44 |
| Air heavy | 10 / 4 / 20 | 8 | 12 | 24 | 320 / 180 | 76 × 44 | -18 / 48 |

Timing is in 60 Hz ticks, geometry in arena units, velocity in units/s. Air heavy,
cooldown, hitstun, volumes, knockback and launch values are local provisional
choices. Default hurt radius/height is 16/44; HP is 100. Configuration expects
positive integer phase/hitstun durations, nonnegative cooldown/damage/velocities,
positive dimensions and unique fighter IDs; arbitrary untrusted config loading
is not implemented. Every repeat attack cycle exceeds its hitstun duration.

Scope deviations from the broader Chat 02 milestone: separate J/K attacks replace
the proposed three-light/fourth-heavy combo for this foundation. CPU, dash, upper,
pursuit, guard/healing, specials and meters remain deferred. P2 stays stationary
except hit reactions. Both fighters use the same combat logic and can accept
inputs in tests or a later controller.

Chat 03 requests replaceable art and gameplay-owned timing. Existing original
geometric robots, cyan/amber palette, ground shadows, depth sorting and dark
grid arena are preserved. Procedural trails and sparks are new original artwork.
`FighterView` and `CombatView` read state/events only and can be replaced without
changing combat. The existing 960×640 fit canvas is retained instead of switching
to the proposed 320×240/64×64 sprite pipeline. Full sprite sheets/manifests,
portraits, selection screens, mobile controls and match timer are deferred.

fresh-attack behavior, simultaneous trades, interruption, hitstun, launch during
landing, all bounds, KO, configurable stats and movement equivalence. All nine
original queued-jump regression cases remain, with ten attack/reset cases added.

Browser validation uses real keyboard movement/jump, then the real Phaser scene
with controlled render deltas at 10/30/60/144/240 Hz. It checks short taps, zero-tick
retention, repeat suppression, blur, single damage, heavy knockback/landing,
vertical misses, visible health text, hitstun and impact-effect creation, with no
runtime exceptions. Controlled deltas are not a hardware performance benchmark.
The script renders its final frozen impact state and saves
`artifacts/m01-3-combat.png` (ignored). Browser testing is development-only; no
test hooks are exposed in the production bundle.

To repeat browser validation after `npm ci`:

```sh
npx playwright install chromium
npm run test:browser
```

The script starts/stops its own local server on port 4174. `CHROMIUM_PATH` can
select an installed Chromium binary; this was used for the local run. CI installs
Playwright's matching Chromium and runs the same checks after tests/typecheck/build.
The PR's Checks tab is the authoritative result for the final commit's CI run.
No merge is performed by this workflow.

Known limits: prototype tuning needs playtesting; short phases can occur wholly
between slow renders even though simulation hits remain correct; close-range
diagnostic labels can crowd; Vite reports the existing large Phaser chunk
(approximately 1.22 MB / 337 KB gzip). No implementation blocker remains locally.
