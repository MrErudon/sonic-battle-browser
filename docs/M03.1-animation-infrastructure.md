# M03.1 — Character animation infrastructure

Baseline: `206f01b51ed6a703d3c537864b0dd8e0e412b7f1`, merged M02.4 PR #10. M03.1 implements infrastructure only. Trestle, Vela, authored character sheets and presentation polish remain separately gated. No hosting, Cloudflare, deployment visibility, multiplayer, CPU decisions, combat values or match rules are changed.

## Architecture

- `src/presentation/manifest.ts`: version-1 character data types, strict runtime validation, immutable copies, five authored/eight logical directions, explicit mirroring, clip aliases and visual attachment transforms. It imports no Phaser code.
- `snapshot.ts`: immutable scalar fighter/projectile snapshots and accepted/contact/projectile/lifecycle DTOs. No mutable simulation objects cross the presentation port.
- `capture.ts`: scene-owned per-tick inbox, clocks, epochs, reaction ages and bounded event queue. Events are captured even if a low-rate render skips an entire phase.
- `resolver.ts`: pure pose selection from authoritative state/phase, including all 28 animation keys. No animation callback changes simulation. Positions are projected then pixel-rounded for drawing; depth remains unrounded ground Y.
- `CharacterAssetLoader.ts`: manifest validation, PNG decoding/dimension checks, nearest filtering, shared texture registration and abortable scene loading. Missing/invalid assets return failure and leave a playable geometric fallback. Partial texture registration is rolled back.
- `SpriteFighterView.ts`: sprite, grounded shadow and debug label; retains `FighterView` as the fallback. Runtime missing-frame detection also falls back. Small read-only diagnostics support browser verification.
- `EffectRegistry.ts` / `effects.ts`: stable effect IDs, replaceable render callbacks and a 32-slot preallocated graphics pool. Contact outcomes select block/break effects before finisher impacts. Special cast/projectile adapters continue to consume simulation state; transient impacts, emission and KO effects consume captured events.

`ArenaScene` binds these adapters and owns cancellation/disposal. `MatchView` and its accessible selectors are unchanged. `main.ts` retains the 960 × 640 canvas and enables pixel-art/round-pixel rendering. The responsive FIT layout is retained.

### Narrow core changes

`stepCombat` accepts an optional fifth presentation sink. It publishes accepted actions and copied contact DTOs; projectile creation is observed immediately after the existing spawn call and before projectile collision/removal. The original fourth accepted-attack telemetry callback remains compatible. No timing, geometry, contact aggregation or resolution rules change.

`MatchController.setPresentation()` attaches an optional consumer. Each unpaused host tick publishes a completed immutable snapshot; lifecycle commands also publish state/pause/reset events, including zero-tick transitions. The existing advance accumulator and tick sequencing are preserved. Cosmetic result/menu ticks can animate without advancing combat. Consumer exceptions are contained so a broken renderer cannot abort a combat transaction. The port is passive by contract; consumers must not retain a separate mutable reference to a match and issue commands from callbacks.

The simulation does not load atlases, query texture dimensions, wait for image decoding or consume presentation events.

## Manifest and resolver examples

The bundled registry lives in `src/presentation/character-registry.json`. Registry changes therefore update the hashed application bundle; they do not depend on changing hosting cache rules. Asset packages themselves use immutable version paths. Publish a new path/version when replacing an existing package.

```json
{
  "schemaVersion": 1,
  "slots": {
    "P1": "characters/synthetic/v1/manifest.json",
    "P2": "characters/synthetic/v1/manifest.json"
  }

```

## Animation contract

Idle/movement, takeoff/ascent/apex/descent/landing, light stages 1–3, heavy/finisher, aerial light/heavy, block startup/hold/stun/release, guard break/recovery, hit reaction/stun/knockback, three specials, KO and victory are covered.

Normal/special phase drawings are sampled from action frame and configured phase duration. First/last tick tests cover all phase boundaries, including first/last drawing selection. Block and landing sampling use copied configured durations. Guard recovery art occupies the final six existing break ticks; it adds no recovery. Jump takeoff is the first airborne tick, not a new startup delay. Hit reactions restart on a new contact, not on an incidental landing-state change. Match winner victory is a cosmetic override over frozen non-KO actions. KO pose age persists across Round Over → Match Over.

There is no position extrapolation or added interpolation latency. At 10 Hz a pose may be skipped; captured effects keep their original tick age and expire rather than replaying stale combat. Help/focus pauses freeze animation clocks. Lifecycle reset epochs prevent reused round-local IDs from suppressing new events.

## Synthetic assets and provenance

`public/assets/characters/synthetic/v1/` contains the transparent PNG, complete manifest and provenance record. `scripts/generate-synthetic-atlas.mjs` deterministically creates simple original diagnostic rectangles, direction markers and pose bars using standard Node PNG/zlib code. No image library, external artwork, Sega input or generative-image asset is used. The synthetic fixture is dedicated under CC0-1.0; it is not a character design delivery.

The validator checks package paths, page limits, 64 × 64 untrimmed/unrotated rectangles, exact pivot, required directional mapping, complete clips, valid aliases, PNG dimensions and provenance. The synthetic PNG hash is checked against its provenance. `assets:check` also regenerates bytes in memory and compares all committed synthetic outputs.

Normal asset failure leaves the menu, input, scoring and match usable. A package can be replaced through registry/manifest/assets without changing combat code. Custom effect render callbacks can be registered by stable effect ID without changing simulation.

## Resource measurements

The synthetic package uses one **544 × 272 RGBA** page shared by both fighter instances:

- PNG: **2,554 bytes**.
- Manifest + PNG: **38,722 bytes** before HTTP compression.
- Decoded pixels: **591,872 bytes** (~578 KiB).
- Estimated RGBA GPU texture: **591,872 bytes**, excluding driver overhead.
- Up to 32 pooled transient effects; bounded 512-event inbox and 256-entry effect deduplication cache.
- Normal application bundle measured at approximately **24.4 KiB gzip**, with Phaser unchanged at **332,184 gzip bytes**. Exact generated bundle and asset measurements are uploaded by CI.

These are texture-byte estimates, not whole-process heap measurements. CPU/GPU copies may coexist. The new browser benchmark measures adapter synchronization CPU time only; it excludes asset decode, GPU rendering and display scanout. DPR/browser-clock tests are simulated display conditions, not physical 240 Hz hardware certification.

The normal production build excludes `presentation-fixture.html` and its test API. `build:fixtures` is an opt-in validation build, used only after the unchanged production checks. No new route/configuration is added to the production hosting setup.

## M03.2 integration and limitations

M03.2 should supply the approved Trestle package using 64 × 64 frames, (32,56) pivots and five authored directions; include all required clips, documented aliases and provenance. Update the presentation registry, run validators and preserve existing simulation tests. Distinct Vela artwork and final effect polish remain M03.3.

Synthetic states intentionally share diagnostic poses. Pixel-art styling, silhouette readability, natural foot motion, final sound/effects and human animation acceptance are not completed here. Fractional responsive CSS scaling can produce uneven physical pixel widths despite nearest filtering. Renderer callbacks are trusted project code, and versioned texture identity requires publishing changed assets under a new version/path.

Independent review should focus on passive event ordering, observer isolation, load cancellation/restart races, missing-asset fallback, phase/anchor correctness and resource ownership. Leave this PR unmerged for review.

The M02.4 backlog remains unchanged: overall damage reduction missed target; whiff rate and received guard breaks increased; no-progress diagnostics and strict difficulty ordering failed. Independent M02.4 review and human M02.1–M02.4 gameplay/balance testing remain pending. This milestone does not resolve or retune those findings.
