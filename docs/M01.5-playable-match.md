## Play and controls

Open the game, choose Easy / Normal / Hard, and select **Start Game**.
You control the cyan robot; the CPU controls amber.

| Control | Action |
| --- | --- |
| WASD / arrow keys | Screen-relative movement and facing |
| Space | Jump (press edge) |
| J | Light attack (press edge) |
| K | Heavy attack (press edge) |
| Jump + attack | Aerial attack |
| Controls / Help or Escape | Open help and pause |
| Escape / Back to game in help | Close help and resume |
| Menu | End the current match and return to difficulty selection |
| Rematch on results | Start a fresh match with the same difficulty and seed |
| Debug | Show coordinates, locomotion, action, facing, seed and state |

Move toward the opponent to face it before attacking. Tap attacks; holding a
key does not auto-repeat. After countdowns, pauses or round transitions, release
and press controls again. Tab/Enter/Space work with native menu buttons.
The previous training shortcuts R and 1/2/3 are retired: difficulty belongs to
the menu, and rematches belong to the results screen.

## Rules

- Best of three: first to **two round wins** takes the match. No match timer.
- Menu → Countdown (180 simulation ticks / 3 seconds) → Fighting.
- Fighting runs the existing combat simulation at exactly 60 Hz.
- All contacts resolve before examining health. One surviving fighter earns
  one point. Both at zero is **Double KO**, no points awarded.
- Every KO enters Round Over for 120 ticks / 2 seconds. Physics, attacks,
  CPU decisions and fighter animation poses freeze at the KO. Existing impact
  sparks may fade; they do not affect combat.
- If either score is two, Round Over → Match Over. Otherwise start a fresh
  countdown, incrementing the round only for a decisive result.
- Double KO replays the same round, positions and seed. Repeated draws can
  continue indefinitely; there is deliberately no sudden-death rule.
- Every round recreates both fighters and the CPU. Health, position, facing,
  height, velocity, landing recovery, action, cooldown, hit-target sets,
  knockback, CPU reaction/interval/pause state and local RNG all reset.
- Each round uses the match's original seed (default 1, zero also valid).
  Rematches use that seed too. Identical inputs reproduce identical rounds.
- Help, browser blur and hidden documents pause all match timers and simulation.
  Focus return does not close help. Paused time is never caught up.
- Difficulty changes are accepted only in Menu. Selection and CPU creation
  happen synchronously, so display/configuration agree even with zero ticks,
  immediate blur or rapid clicks. Difficulty remains fixed throughout a match.

## Architecture

`src/core/match.ts` contains the Phaser/DOM-independent `MatchController`
and `MatchInput`. The controller owns scoring, state transitions, fighters,
CPU lifetime, fixed-step scheduling and reset signaling. `tick()` advances
one fixed tick; `advance(deltaMs)` accumulates fractional ticks and bounds
stall catch-up to six ticks. UI commands are synchronous transactions;
combat advances only in Fighting. Countdown's final tick enters Fighting
without executing combat on that same tick.

`MatchInput` captures keyboard edges independently of render timing. Very
short press/release pairs survive zero-tick renders. Multiple pending attacks
coalesce with first attack winning. Consumption occurs once per simulation
tick; combat's ordinary recovery/landing/hitstun rules discard invalid actions.
Every match boundary clears pending edges and active movement. Physical-held
tracking prevents a held key from crossing a boundary without release. Blur
also clears physical-held tracking, while repeat events remain ignored.

`ArenaScene` translates browser key/focus/visibility events, calls the
controller, and renders results. No Phaser key polling is needed. Shutdown
removes listeners and the DOM UI; restart has browser regression coverage.
`resetVersion` tells renderers to clear sparks and trails even after zero-tick
menu/rematch commands. Help preserves menu focus; closing help during play
returns keyboard control to gameplay. Native interactive controls retain
Space/Enter semantics. Diagnostics are off by default.

`MatchView` and `style.css` are replaceable presentation. Native buttons,
progress elements, numeric health, explicit player labels, visible focus,
a modal help dialog and status announcements provide accessible UI controls.
The canvas combat itself is visual and is not a screen-reader-accessible game.
No simulation behavior depends on animation or UI callbacks completing.

## Remaining scope limits

Desktop keyboard prototype, no touch/gamepad/multiplayer/audio/save support.
Small-screen menus fit, but combat still needs a keyboard. Provisional CPU
balance is exploitable by aggressive light attacks; this milestone preserves
existing combat stats and decisions rather than rebalance them. No special
moves, blocking, combos, tactical retreat or prediction. Replays reset to the
same seed intentionally. Draws have no retry cap. Browser gameplay validation
uses deterministic accelerated matches, not a claim of human playtesting or
comprehensive cross-browser/mobile certification.

PR must remain open and unmerged for independent review. The final PR description
records the exact delivered SHA, CI run URL and its outcome.
